# ТЗ по лендингу — Tovarische (рабочее название)

> Платформа попутной доставки посылок между городами. "Как BlaBlaCar, но для вещей."
> B2C, MVP-этап. Цель лендинга — проверка гипотезы ценности: нужен ли рынку такой продукт, кто реальная ЦА (отправители vs перевозчики).

## Общие принципы

- Лендинг презентует продукт как полноценный и готовый к использованию. Никаких пометок "скоро"/"в разработке" на лендинге — это ограничение UI внутри платформы после регистрации, не публичной витрины.
- Никакого слова "тестирование" в текстах — сервис подаётся как рабочий продукт.
- Копирайтинг: коротко, прямо, без канцелярита и надуманных конфликтов. Одно чёткое утверждение лучше развёрнутой метафоры.
- Обе роли (отправитель и перевозчик) равнозначны — нет главной/второстепенной роли, нет доминирующего CTA.
- Юридические риски и ограничения упоминаются компактно, только в FAQ — не пугающим блоком на видном месте.
- Цветовая палитра — из презентации 2021 года (мятно-розово-фиолетовые градиенты), не из референса Semrush.
- Стиль отдельных блоков (карусель карточек, крупные statement-цифры, hero с формой) — по референсу Semrush, но без переиспользования самого дизайна макетов приложения из старой презентации.

---

## Контекст продукта (для справки, не часть текста лендинга)

**Целевая аудитория MVP:** физические лица, которым нужна срочная или бюджетная доставка между городами (1 этап роста ЦА — далее малые предприятия, затем крупные компании и интернет-магазины на следующих этапах). B2C-фокус.

**Платформа:** только веб-версия, без мобильного приложения.

**Монетизация:** отсутствует на MVP-этапе намеренно. Сервисный сбор из презентации 2021 года (~50 руб./заказ) сейчас не внедряется и не отображается на лендинге — поэтому в навигации нет пункта «Тарифы». Юридическое оформление и монетизация — предмет отдельного обсуждения после проверки гипотез.

**Канал привлечения первых пользователей:** тематические Telegram-чаты по перевозке посылок (Москва, Санкт-Петербург и др.) — важно для настройки аналитики, см. раздел «Метрики».

## UI/UX-паттерны для реализации (референс Semrush)

Из присланного референса берём поведение интерфейса, а не визуальный дизайн (цвета и стиль — из презентации 2021 года, мятно-розово-фиолетовые градиенты):

- **Блок 4 (карточки-половинки):** прямоугольник переключается на соседнюю карточку при наведении курсора (hover-switch), а не по клику.
- **Блок 6 (карусель преимуществ):** раскрывающиеся карточки с иконкой плюс/крест, стрелки навигации влево/вправо, горизонтальный скролл при большом числе карточек.
- **Крупные цифры/статы (если понадобятся):** подсвечиваются по мере скролла страницы — триггер на позицию блока на экране, а не на курсор.
- **Блок 8 (финальный CTA):** контрастный тёмный блок на светлом фоне остальной страницы — визуальный якорь перед футером.

## Блок 5. Как это работает

1. **Заявка** — отправитель описывает посылку и маршрут, перевозчик — свою поездку
2. **Поиск** — система подбирает подходящие совпадения по маршруту и датам
3. **Договорённость** — стороны списываются напрямую и подтверждают сделку
4. **В пути** — посылка едет, отправитель видит статус
5. **Готово** — посылка доставлена, получатель подтверждает получение

## Блок 7. FAQ

Компактный блок, включает юридическую часть без запугивающих формулировок:

- **Что можно отправлять через сервис?** — короткий честный ответ, список того, что нельзя пересылать (запрещённые/опасные вещества и предметы), ответственность за содержимое посылки на стороне отправителя.
- **Кто отвечает за сохранность посылки?** — ответственность на сторонах сделки (отправитель/перевозчик), сервис — площадка для поиска и связи, не логистическая компания.
- **Как происходит подбор попутчика?** — система показывает подходящие по маршруту и датам заявки.
- **Безопасно ли это?** — прямая связь, подтверждение сделки на платформе, отзывы и рейтинги (когда доступны).
- **Нужно ли подтверждать почту при регистрации?** — нет, упрощённая регистрация без верификации email на этом этапе.

## Флоу регистрации (после лендинга, отдельные экраны — не часть самого лендинга)

1. **Шаг 1 — базовая форма:** email + пароль. Без подтверждения почты (убираем на MVP ради простоты).
2. **Шаг 2 — выбор роли (обязательный, одна роль):**
   - Отправитель/получатель
   - Перевозчик
   Взаимоисключающий выбор (radio, не чекбокс) — нужен для сегментации аналитики ЦА с первого шага.
3. **Шаг 3 — анкета-профиль (необязательная, можно пропустить):** имя, фото, короткое "о себе". Не блокирует доступ к платформе.

## Функционал платформы vs лендинг (для разработки, не для копирайта)

Лендинг говорит про все фичи как про доступные. Внутри платформы после регистрации статус фактического функционала:

*(Детальная карточка заявки — габариты, вес, даты, фильтры поиска — отдельный ТЗ на функционал платформы, прорабатывается на следующем этапе после проверки гипотез через лендинг.)*

| Фича | Статус на MVP |
|---|---|
| Публикация заявки (отправитель) | Доступно |
| Публикация поездки (перевозчик) | Доступно |
| Поиск/фильтр по маршруту и датам | Доступно |
| Прямая связь между сторонами | Доступно |
| Подтверждение сделки | Доступно |
| Отслеживание статуса | Доступно (базовое, ручное обновление статуса) |
| ИИ-подбор попутчиков | В разработке — в интерфейсе помечается "скоро" |
| Рейтинги и отзывы | В разработке — в интерфейсе помечается "скоро" |
| Страховка заказа | Не в MVP |
| Оплата через платформу | Не в MVP — стороны договариваются напрямую |

## Метрики для проверки гипотез (MVP-цель)

- Количество визитов/кликов на лендинг
- Конверсия в регистрацию
- Разбивка зарегистрированных по ролям (отправитель vs перевозчик) — ключевая метрика для понимания реальной ЦА
- Количество созданных заявок (отправка) и поездок (перевозка)
- Количество состоявшихся "матчей" (подтверждённых сделок между сторонами)
- Целевое событие-мечта: хотя бы одна посылка реально передана через платформу и перевозчик получил вознаграждение
- Источник трафика по UTM-меткам — отдельная ссылка на каждый Telegram-чат, куда будет распространяться лендинг, чтобы видеть, какой чат/город даёт больше конверсий
- Подключить простую веб-аналитику (Яндекс.Метрика или аналог) уже на этапе лендинга, до старта рассылки по чатам
